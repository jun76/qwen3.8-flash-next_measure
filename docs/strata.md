# Strata / Qwen3.8 Flash Next 速度比較

測定日：2026年9月28日。ユーザープロンプトは全測定で **「ブロック崩しゲーム作って」**。

S01–S31は本実験内で付与した設定IDで、Strataの起動引数の組み合わせを表す。[呼称と使用エンジン](../README.md)を参照。

**サーバー設定31種類、入力・出力条件を含めて36条件、合計45回測定した。**

S31はexpertのGPU常駐枠を増やし、適応的な入れ替えを4ラウンドごとから毎ラウンドへ変更した構成。
再起動して行った3回の固定長測定と、応答終了までの測定の両方で基準設定S01を上回った。
測定後の空きVRAMは約1.4〜1.7GiBで、コンテキストは262,144を維持した。

固定長の再測定の中央値では、基準設定S01に対して約19%改善した。

MTP幅・候補閾値、CPUワーカー数、CPU/GPU分担、expertキャッシュ容量と入れ替え頻度、コンテキスト、KV形式、prefill、転送方式、PLE表の読み方を試した。全組み合わせの網羅ではなく、途中の結果から候補を絞り、S31で有力な変更を組み合わせた。過去のllama.cpp測定はこの回数に含めない。

## 4. 比較方法と読み取れる範囲

- RTX 5090 32GB、Core i7-14700、RAM128GB、M.2 SSD上の同じGGUFを使用。比較用APIは8082番ポート。別のLLMエンジンは同時実行しなかった。
- Harness入力はllama.cpp比較時の保存済みメッセージと27個のツール定義を再使用した。ユーザープロンプトは同一。テンプレートの整形が異なるため、Strataでは8,685入力トークン、以前のllama.cppでは8,930だった。
- 「直接」はツール定義を付けず、ユーザープロンプトだけをAPIへ渡した。Harness入力とは別条件として数える。
- 全測定で`--prompt-cache 0`。再利用トークン数は全て0。測定に使用したStrataサーバーはgreedy生成で、temperatureを変えても反映されない。思考なしは`chat_template_kwargs.enable_thinking=false`。
- native IQのサーバーには`spec >= 2`とMTP headが必要なため、MTP完全無効化は測っていない。高い候補閾値もMTP無効化とは区別する。
- S01・S30・S31と短文候補S24をそれぞれ再起動して3回、S29を2回測定。他の設定は1回の探索なので、小差を確実な優劣とは扱わない。
- このプロンプトではcacheの適応的な入れ替えを止めるS23が大きく遅くなった。転送をdirectにするS26、PLEをmmapにするS25も改善しなかった。MTP幅を大きくするだけでは速くならなかった。
- 同じプロンプトでも生成されるトークン列や候補採用率は設定・実行ごとに変わった。単一の出力列を固定して計算だけを比較した測定ではない。別のプロンプト、長い履歴、並行利用で同じ速度が出る保証はない。
