# Qwen3.8 Flash Next / llama.cpp 速度調整結果

測定日：2026年9月28日。ユーザープロンプトは全測定で **「ブロック崩しゲーム作って」**。

U1–U5とG1–G7は本実験内で付与した設定ID。UはUnsloth版llama.cpp、GはGenerelSchwerz版llama.cppの起動引数の組み合わせを表す。[呼称と使用エンジン](../README.md)を参照。

## 1. 試したバリエーションの総数

**2系統のエンジンでサーバー設定を12種類試し、入力などを変えた21条件を、合計22回測定した。**

| エンジン | サーバー設定の種類 | 入力・生成パラメーターを含む条件数 | 測定回数 |
| --- | ---: | ---: | ---: |
| Unsloth版 llama.cpp | 5 | 7 | 7 |
| GenerelSchwerz版 llama.cpp | 7 | 14 | 15 |
| **合計** | **12** | **21** | **22** |

- **サーバー設定**：MTP、コンテキスト長、CPUスレッド、KV形式、MoEキャッシュ、追加最適化などの組み合わせ。次の表でU1〜U5、G1〜G7と表記する。
- **条件数**：サーバー設定に加え、入力、temperature、思考の有無、出力上限を区別して数えたもの。同じ設定で入力や出力上限を変えた測定も含む。
- **測定回数**：実際に生成リクエストを送った回数。No.20はNo.18と同じ条件をサーバー再起動後に再測定したもの。表示用モデル別名の変更は別条件に数えていない。

AtomicBotは対応状況の調査のみで、実行回数に含めない。Strataは別の測定群であり、llama.cppの22回には含めない。途中の結果を見て候補を絞った探索であり、各パラメーターの全組み合わせを網羅したものではない。

- 本体モデルは全設定で同じ **GSQ-RCO IQ3_Sの2分割GGUF**。MTP headのQ4/Q8と、本体・KVの量子化は別の設定。
- 追加最適化「あり」は、`backend-sampling`、`decode-overlap`、`decode-boundary-overlap`、`ple-prefetch`、`phase-aware-workspace`、`live-context-workspace`をまとめて有効化した構成。個々の機能を単独で比較した結果ではない。
- Generel版は全GPU層指定、`fit off`、`load-mode none`、`lazy-mode on`、batch/ubatch各512。Unsloth版はfitによる配置調整を使用。入力処理用スレッドは全設定20。
- 起動設定は[profiles.json](../configs/llama_cpp.json)に保存。G1では追加の実験ログ出力も有効。G7の表示用別名・全起動引数は[../configs/llama_cpp.json](../configs/llama_cpp.json)を参照。

## 4. 測定方法と比較上の制約

機材はRTX 5090 32GB、Core i7-14700、RAM 128GB（64GB×2、DDR5-5600）。
全測定でM.2 SSD上の同じ本体モデルを使用した。

速度はサーバーが返した`timings.predicted_per_second`で、入力処理を除いた生成区間全体の平均。思考ありでは思考トークンも含む。入力処理時間・生成時間・リクエスト全体の時間は[CSV](../results/llama_cpp/results.csv)に別々に保存した。

全リクエストはseed 1234、top_k 20、top_p 0.95、min_p 0.05、`cache_prompt=false`。temperature、思考、出力上限の違いは上の一覧に明示した。Harness入力の再現測定にはブラウザ描画やツール実行の時間を含めない。

各条件は原則1回、再測定はNo.18/20の1組だけ。
生成内容と長さが異なる行や、複数の設定を同時に変えた行もあるため、表全体を同一条件の順位表として扱うことはできない。
MTPだけの効果をすべての構成で分離して測ったわけではない。
